# Dire Wolf Station — Windows GUI for Dire Wolf

A Windows 10/11 desktop application that runs [Dire Wolf](../README.md) as its packet modem
and TNC and puts station setup, operation and troubleshooting in one window.  Dire Wolf
stays the authoritative modem and protocol backend: the GUI uses its real command line
options, configuration file, console output, AGWPE and KISS interfaces and CSV log.  It
does not contain a modem or a TNC of its own, and plain command-line Dire Wolf does not
depend on it.

User documentation: [docs/USER_GUIDE.md](docs/USER_GUIDE.md).

## Layout

| Path | What |
|---|---|
| `src/DireWolfGui.Core` | Station logic without UI (net10.0, platform neutral, no NuGet packages): process control, console parser, AGW/KISS clients, APRS, configuration document, validation, backups, profiles, settings. API: [docs/CORE_RUNTIME_API.md](docs/CORE_RUNTIME_API.md), [docs/CORE_CONFIG_API.md](docs/CORE_CONFIG_API.md). |
| `src/DireWolfGui` | The WPF application (net10.0-windows, MVVM, Fluent theme). Executable `DireWolfStation.exe`. |
| `tests/DireWolfGui.Core.Tests` | xUnit tests for Core, including integration tests that run the real `direwolf`. |
| `scripts/package.ps1` | Builds the portable ZIP. |
| `IMPLEMENTATION_CHECKLIST.md` | Short progress list for contributors. |

## Build

Requirements: .NET 10 SDK.  Building Dire Wolf itself is described in the main README
(on Windows: MinGW, as in `.github/workflows/ci.yml`).

```
dotnet build windows-gui/DireWolfGui.slnx -c Release
```

The WPF project also *compiles* on Linux and macOS (`EnableWindowsTargeting`), which is how
it is checked in the Linux CI job; it only *runs* on Windows.

## Test

```
# optional: point the integration tests at a direwolf build (default: <repo>/build/src/direwolf[.exe])
set DIREWOLF_EXE=C:\path\to\direwolf.exe          (PowerShell: $env:DIREWOLF_EXE = "...")
dotnet test windows-gui/DireWolfGui.slnx -c Release
```

* Unit tests cover the configuration document (byte-exact round trip of every sample
  configuration, targeted edits), the directive catalog (checked against `src/config.c`),
  validation, backups, profiles, settings, console output parsing, AX.25, AGW and KISS
  codecs and clients (against loopback servers), APRS parsing, the CSV log tailer, the
  station tracker, APRS message retries/acks and redaction of credentials.
* Integration tests start the real `direwolf` with audio generated by `gen_packets` on
  standard input: received packets and audio levels, AGW monitor and raw frames, KISS,
  transmission through AGW, the CSV log, clean stop (Ctrl+C / SIGINT), start failures and
  `--check-config`.  They are skipped with a reason when no direwolf build is found; the
  ones that need an audio output device are skipped on Windows machines without one.
* `DireWolfStation.exe --smoke-test report.txt` opens every page in both themes and fails
  on WPF binding, resource or XAML errors.  The Windows CI job runs it.

## Package

```
pwsh windows-gui/scripts/package.ps1 -DireWolfDir build/src
```

Creates `windows-gui/dist/DireWolfStation-<version>-win-x64.zip`: a self-contained,
single-file `DireWolfStation.exe` (no .NET installation needed) plus, with `-DireWolfDir`,
`direwolf.exe` and its data files in a `direwolf` folder.  `-SelfContained:$false` makes a
small ZIP that needs the .NET 10 Desktop Runtime.  Unzip anywhere and run; nothing is
installed and nothing is written outside `%APPDATA%\DireWolfStation` and
`%LOCALAPPDATA%\DireWolfStation`.  The Windows CI job publishes the ZIP as an artifact.

## Backend additions used by the GUI

All opt-in; existing configurations and command lines behave as before (see `CHANGES.md`):

* `direwolf --check-config` — validate a configuration with the real parser without
  opening audio, PTT or network ports; machine readable summary.
* `TCPBIND LOCAL` — AGW and KISS TCP servers accept connections only from this computer.
  The setup wizard writes it by default.
* On Windows, stdout is unbuffered when redirected, so the GUI receives the log live.

Older Dire Wolf builds still work: configuration checks then fall back to the GUI's own
validation (and say so), and log lines may arrive in bursts.

## Design rules

* Nothing transmits because the GUI started.  Transmitting or forwarding features are only
  enabled by explicit user action with a confirmation; the header shows whether the
  configuration transmits on its own.
* Configuration edits are targeted: comments, order and unknown directives are kept, every
  save shows a diff, makes a backup and is atomic.
* No fabricated data: positions come from Dire Wolf's decoder (CSV log) or a strict APRS
  parser, acknowledgements only from received acks; age and source are shown.
* APRS-IS passcodes are never logged or stored in settings.
* No cloud services, telemetry or advertising.  Map tiles are off unless enabled.

## Verification status

Done in the development environment (Linux): Core unit and integration tests against a real
Linux `direwolf`; the WPF project compiles.  Done by CI on Windows: MinGW build of Dire Wolf,
its `ctest` suite, the Core tests against `direwolf.exe`, packaging and the GUI smoke test.
Not done by automation: interactive use on a Windows desktop with a real sound card and
radio (audio device selection, level meter, PTT, Ctrl+C stop of a live `direwolf.exe`).
